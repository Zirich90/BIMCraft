# СПС и СОУЭ через CLI и MCP

Для отдельной копии проекта запусти `bimcraft-cli mcp` и вызови `open`
с абсолютным путём. Чтобы работать с проектом, открытым пользователем,
включи File > Settings > Agents в BIMCraft и запусти
`bimcraft-cli mcp --connect`. Для обследования добавь `--read-only`:
в отдельном сеансе укажи исходный файл в командной строке запуска.
В открытом окне новый проект или другой файл выбирает пользователь.

Вызови `inspect_model`, чтобы сверить имя проекта, уровни и предупреждения.
`list_commands {"filter":"fire_"}` показывает актуальные параметры
и доступные имена. Даже команды без кнопки в меню вызываются через
`execute {"command":"имя","params":{...}}`. В CLI каталог выдаёт
`bimcraft-cli commands`. Для пакетной работы передай в MCP `script`
текст с одной строкой `команда {JSON}` на вызов. Проверь изменения через
`dry_run:true`, затем выполни с `atomic:true`, чтобы собрать правки
модели в один шаг отмены. Файловый экспорт запускай отдельным вызовом.

## Порядок работы

| Задача | Команды и результат |
| --- | --- |
| Исходная модель и каталог | `query_elements` для поиска по категориям и этажам. `adapt_ifc` для адаптации связанной модели. `catalogue_import` или `catalogue_link` для ODS, `catalogue_pending` для ещё не использованных позиций, `catalogue_sync` для синхронизации, `catalogue_export` для выгрузки каталога. |
| Приборы и зоны | `component` размещает приборы, `equipment` добавляет позиции в спецификацию. `resat` оценивает скрытые пространства, `detectors` рассчитывает расстановку, `fire_zone` задаёт и проверяет зоны. |
| Кабели и линии | `wire` строит кабель, `wire_connect` подключает конец, `electrical_terminal` задаёт клемму. `electrical_line` принимает источник, приборы и участки. Проверяй связи через `electrical_line_inspect`, редактируй через `electrical_line_edit`, управляй маркировкой через `electrical_mark_template`, `electrical_line_mark` и `electrical_line_renumber`. Длины и запас смотри в `cable_journal`. |
| КНС | `cable_carrier` строит трассу по точкам или существующим кабелям, `carrier_section` задаёт паспортное внутреннее сечение. `cable_carrier_candidates` показывает кандидатов для привязки; `modify` сохраняет выбранную связь. `cable_carrier_check` с `mode:"warn"` без `configure:true` проверяет заполнение; `mode:"auto"` может менять типоразмеры. |
| Отказы линии | `fire_line_faults` проверяет обрывы и КЗ. `fire_isolator` показывает предложенную установку; `apply:true` ставит изолятор и изменяет кабель. Перед применением проверь тип прибора и повтори расчёт после изменения. |
| Нормативные расчёты | `fire_line_load` — токи по режимам, `fire_voltage_drop` — напряжение радиальной цепи, `fire_battery` — АКБ, `soue_amplifier_load` — нагрузка усилителя, `soue_sound_check` — контрольные точки, `fire_carrier_parts` — оценка комплектующих, `fire_okl_check` — сверка с испытанной конфигурацией. |
| Текущий выпуск | `schedule` строит таблицу. `render` проверяет план, 3D или лист. MCP `save` с путём к новому `.pdf` печатает существующие листы. Автоматическая структурная схема и выпуск полного комплекта по шаблонам LibreOffice относятся к [этапу 8](../low-voltage-roadmap.md). |

Для устойчивых ссылок используй GUID из результатов запроса. Координаты
и длины в командах по умолчанию в миллиметрах. Явные суффиксы задают
другие единицы: `length_m`, `ohm_per_km`, `load_ma`, `standby_a`,
`required_min`. Токи, пределы и характеристики ОКЛ бери из паспортов
и протоколов. Проверь статус отчёта, поля пропусков и нарушения. Успешный
вызов команды может вернуть перегрузку или неполные данные.
Контрольные значения и допущения описаны в [справочнике нормативов](low-voltage-standards.md).

## Контрольный вызов

В отдельном пустом сеансе передай MCP-инструменту `script` следующие
строки с `atomic:true`. В последнем элементе `results` ожидаются
`required_ah:19.375`, `fire_runtime_h:16`.

```text
component {"family":"Fire Alarm Panel","at":[0,0]}
component {"family":"Smoke Detector","at":[1000,0]}
fire_battery {"standby_a":0.25,"fire_a":1.5,"source_a":0.25,"end_capacity_percent":80,"standby_load_factor":1,"fire_load_factor":2,"installed_ah":30}
```

Для расчёта линии возьми ID или GUID из ответов `component`. Передай их
в `electrical_line` как `source` и `devices`. ID созданной линии передай
в `fire_line_load` вместе с паспортными `loads` по приборам.

## Границы доступа

- Режим только чтения позволяет инспектировать модель, запускать расчёты
  и экспортировать результат в новые файлы. Для записи в модель нужен
  режим редактирования. `catalogue_sync {"read_only":true}` пропускает
  запись в ODS, но может принять новые строки в модель.
- Открытие диалогов и редактирование незавершённого эскиза принадлежат
  окну. Чтобы получить тот же контур через MCP, передай итоговые кривые
  или границу непосредственно команде создания либо изменения элемента.
- Для снимка именно открытого окна используй `capture` через
  `mcp --connect` с `revision` из свежего `inspect_model`.
