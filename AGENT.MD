# BIMCraft — правила нашей доработки

## Старт работы

- Сразу активируй доступные проектные навыки и хуки. Навыки по умолчанию — `caveman` для кратких ответов на русском, `ponytail` для минимальных полных изменений и `graphify` для навигации по коду. Другие навыки подключай по задаче.
- При старте и после сжатия прочитай `.memory/00_STATE.md`, `.memory/01_BLACKBOARD.md`, относящиеся к задаче решения в `.memory/02_DECISIONS.md` и `graphify-out/GRAPH_REPORT.md`. Проверяй нужные узлы по текущим исходникам и SHA-256. Фиксируй отсутствующие узлы.
- Используй настроенный Stop-хук для финальной проверки Cargo. Делегируй ограниченную рутину через Qwen и общую доску, если связь и доступный резерв GPU подтверждены. Для очереди используй `PENDING_QWEN` без повторного ручного запуска. Архитектуру, проверку diff и приёмку ведёт основной агент. [Регламент памяти и хуков](docs/areas/shared-memory.md) · [Локальный Qwen](docs/areas/local-coder.md).

## Работа с апстримом

- Основа — IPedrax/BIMCraft. Переноси все наши наработки отдельными модулями. В файлах апстрима оставляй объявления, регистрацию и тонкие вызовы. Используй существующие механизмы апстрима там, где они сохраняют наши рабочие сценарии.
- Ядро слаботочки — `crates/core/src/low_voltage/`. UI — `crates/ui-egui/src/low_voltage_ui/` или `low_voltage_ui.rs`. Подключай модель через единые хуки проверки и миграции. Версию данных расширения веди отдельно от базового `FORMAT`. Необязательные поля общих структур сериализуй с `serde(default, skip_serializing_if = "...")`. Проверяй загрузку проектов апстрима и миграцию проектов форка с сохранением GUID и связей.
- Ядро без зависимостей от UI. Изменения модели идут через `Session::execute`, общая валидация через `Model::check`. Ссылки между элементами хранят GUID. Сохраняй атомарный откат и проверяй входные данные. Следуй правилам clean-room и локальным указаниям в крейтах.
- СПС, СОУЭ, СКУД, СОТ и ОТС имеют отдельные профили маркировки, проверок, КНС и выходных документов. Требования и приёмка этапов 8–9 — в [дорожной карте](docs/low-voltage-roadmap.md). Команды — в [руководстве СПС/СОУЭ](docs/areas/low-voltage-agent.md). Форматы выпуска — в [описании документов](docs/areas/low-voltage-documents.md).

## Базовые соглашения BIMCraft

- Регистрируй новые операции через `commands::ALL` с описанием параметров и тестом. Команды разбирают параметры строго. Чтение проекта сообщает о пропущенных полях и отклоняет неподдерживаемый формат.
- При добавлении ссылок учитывай обход GUID в `visit_refs!` и правила библиотеки. Новые экземпляры и копии получают собственные ID и GUID. Файлы и команды используют миллиметры, интерфейс преобразует единицы проекта.
- Проверяй пределы размеров, координат и входных данных. В рабочем коде запрещены `unsafe`, `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!` и `unreachable!`.
- Сетевые запросы приложения проходят через `crates/update`. Подробности реализации держи в локальных документах крейтов и `docs/areas/`.

## Проверки

ВАЖНО (BATCH MODE): Сначала внеси ВСЕ изменения в код по всем пунктам. КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО запускать cargo check / clippy / test после каждой отдельной правки! Запусти проверку СТРОГО ОДИН РАЗ в самом конце, когда все файлы уже изменены.

- Тесты поведения пиши до реализации. Выполняй их в единственном финальном пакете. Поставь пакет в очередь через `python scripts/cargo_stop_hook.py fmt clippy test`. Получи результат той же заявки, сверив код завершения и журнал.
- Проверяй результат через штатный сценарий. Для выпуска ПД открой полученные листы, таблицы и документы. Зафиксируй подтверждённый результат и открытые вопросы в общей памяти.
